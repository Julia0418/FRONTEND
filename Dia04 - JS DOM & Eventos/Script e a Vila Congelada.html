Capítulo 2

A ponte do script.js

O código da Capitã mora num arquivo separado. Para ligá-lo à página, ela constrói uma ponte.

A tag <script src="..."> liga o arquivo script.js ao HTML. Eu fico no final do body.
<!-- No final do index.html -->
  <script src="script.js"></script>
</body>

Por que no final? Porque o navegador lê o HTML de cima para baixo.

Se eu chegar antes dos elementos, não encontro ninguém: o resultado é null!

    Capítulo 4
    Ouvindo o clique
    
    
    
      
    
        
    Achar o formulário não basta. A Capitã quer saber quando ele for enviado.
    
        
    
          
    
            
    
              
    addEventListener é como contratar um vigia: quando acontecer um "submit", execute esta função!
    
              
            
    
            
    formTarefa.addEventListener('submit', function (event) {
  // tudo aqui roda a cada envio
});
    
          
    
        
    
      
    
      
    
        
    Só que o navegador tem um hábito antigo: ao enviar um formulário, recarrega a página.
    
        
    
          
    Nããããão! Eu queria recarregar!
    
          
        
    
      
    
    
    
    
    
      
    
        
    A Capitã usa a ferramenta secreta que vem junto com o evento.
    
        
    
          
    STOP!
    
          
    
            
            
    
              
    event.preventDefault() manda o navegador esperar. Sem ele, a página recarrega e as tarefas criadas somem!
    
              
    formTarefa.addEventListener('submit', function (event) {
  // impede o recarregamento padrão
  event.preventDefault();
});

    Laboratório 5 · textContent ou innerHTML?
    Digite HTML e compare
    
      
    
        
    
          
          
        
    
        
    
          
          
          
        
    
        
    
          
    el.textContent = texto;
    
          
    el.innerHTML = texto;

    Folha de cola da Capitã Script
    
      
    
        
    <script src>
    Liga o arquivo .js ao HTML. Vai no final do body, depois dos elementos.
    
        
    getElementById
    Seleciona pelo id, sem #. Devolve o elemento ou null.
    
        
    querySelector
    Usa seletores CSS (#id, .classe) e devolve o primeiro que combinar.
    
        
    addEventListener
    Escuta um evento e executa a função quando ele acontecer.
    
        
    preventDefault()
    Cancela o comportamento padrão. No submit, evita o recarregamento. Não esqueça os parênteses.
    
        
    .value e .trim()
    Lê o que foi digitado e remove espaços das pontas.
    
        
    createElement e appendChild
    Criam um elemento novo e o penduram dentro de outro.
    
        
    textContent e innerHTML
    Texto puro contra HTML interpretado.
    
        
    reset() e focus()
    Limpam o formulário e devolvem o cursor ao campo.
    
      
    
    
    

    
    
      
    Questões do caderno
    Respostas escondidas: tente antes de abrir
    
      
    
        
    1. O que é o DOM e como o JavaScript o utiliza para alterar a página?
          
    O DOM (Document Object Model) é a representação da página como uma árvore de objetos, criada pelo navegador a partir do HTML. O JavaScript usa essa árvore para selecionar elementos, ler e mudar textos, atributos e estilos, e também criar ou remover elementos, sem recarregar a página.
    
        
    2. Para que serve event.preventDefault() em um evento de formulário? O que acontece se não a usarmos?
          
    Ela cancela o comportamento padrão do evento. No submit, impede que o navegador envie o formulário e recarregue a página. Sem ela, a página recarrega logo depois do nosso código, e tudo o que foi criado dinamicamente (como os novos cards) desaparece.
    
        
    3. Qual é a diferença entre document.getElementById('id') e document.querySelector('.classe')?
          
    getElementById busca apenas por id e recebe o nome sem #. querySelector recebe qualquer seletor CSS (.classe, #id, article h3) e devolve o primeiro elemento que combinar. Os dois devolvem null quando não encontram nada.
    
        
    4. Qual é a diferença entre textContent e innerHTML?
          
    textContent lê ou define apenas texto: se houver tags, elas aparecem escritas. innerHTML interpreta a string como HTML e cria a estrutura. Por isso innerHTML serve para montar o card inteiro, mas exige cuidado com textos digitados por usuários.
